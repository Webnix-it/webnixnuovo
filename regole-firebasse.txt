File di riferimento per la dashboard admin (admin.html).
La configurazione del progetto è già dentro firebase-config.js.

Contenuto:

Le collezioni usate dalla dashboard sono:

  pacchetti    → name, tag, description, price, cta, link
  faq          → question, answer, icon
  impostazioni → documento unico "sito"
                 - colori: { viola, ciano, sfondo, sfondoCard }
                 - link:   { instagram, facebook, email, cookiebot, pixel }

Database Realtime (opzionale): /recensioni


------------------------------------------------------------
1) REGOLE FIRESTORE
------------------------------------------------------------
Console Firebase → Firestore Database → Regole.
Incolla tutto e premi "Pubblica". Se aggiungi altri amministratori,
metti le loro email nella lista di isAdmin().

rules_version = '2';

service cloud.firestore {
  match /databases/{database}/documents {

    // Chi è amministratore: deve aver fatto accesso con Google
    // ed essere nella lista degli indirizzi autorizzati.
    function isAdmin() {
      return request.auth != null
        && request.auth.token.email_verified == true
        && request.auth.token.email in [
             'webnixit@gmail.com'
           ];
    }

    // Contenuti pubblici: tutti possono leggerli,
    // solo l'amministratore può scriverli.
    match /recensioni/{doc} {
      allow read: if true;
      allow write: if isAdmin();
    }

    match /portfolio/{doc} {
      allow read: if true;
      allow write: if isAdmin();
    }

    match /pacchetti/{doc} {
      allow read: if true;
      allow write: if isAdmin();
    }

    match /faq/{doc} {
      allow read: if true;
      allow write: if isAdmin();
    }

    match /impostazioni/{doc} {
      allow read: if true;
      allow write: if isAdmin();
    }

    // Tutto il resto è chiuso.
    match /{document=**} {
      allow read, write: if false;
    }
  }
}

   Authentication → Settings → Authorized domains.

5) MODULO RICHIESTA BOZZA (popup + CRM)
------------------------------------------------------------
Il popup salva le richieste nella collezione "richieste-bozza" e la
configurazione in "impostazioni/modulo-bozza".

La lettura della configurazione è già consentita dalle regole del
punto 1 (impostazioni/{doc}: read true). Per le richieste aggiungi
questi blocchi DENTRO service cloud.firestore, prima del match
finale "Tutto il resto è chiuso":

    // Il visitatore può inviare una richiesta, ma non leggerla.
    match /richieste-bozza/{doc} {
      allow create: if request.resource.data.nome is string
        && request.resource.data.nome.size() >= 2
        && request.resource.data.nome.size() <= 120
        && request.resource.data.email is string
        && request.resource.data.email.matches('.+@.+\\..+')
        && request.resource.data.stato == 'Nuova'
        && request.resource.data.budget is int
        && request.resource.data.budget >= 0
        && request.resource.data.budget <= 1000000
        && request.resource.data.risposte is list
        && request.resource.data.risposte.size() <= 60
        && request.resource.data.allegati is list
        && request.resource.data.allegati.size() <= 4;

      // Solo l'amministratore legge, aggiorna e cancella.
      allow read, update, delete: if isAdmin();
    }

Senza "allow create" il popup mostra l'errore di invio e propone
WhatsApp come alternativa: nessun dato va perso.

------------------------------------------------------------
6) ALLEGATI — FIREBASE STORAGE
------------------------------------------------------------
Console Firebase → Storage → Regole. Il modulo carica i file in
richieste-bozza/ e salva nel documento solo nome, tipo, peso e URL.

    rules_version = '2';
    service firebase.storage {
      match /b/{bucket}/o {
        match /richieste-bozza/{cartella}/{file} {
          // Il visitatore può caricare solo immagini e documenti,
          // fino a 4 MB per file.
          allow create: if request.resource.size < 4 * 1024 * 1024
            && request.resource.contentType.matches('image/.*|application/pdf|application/msword|application/vnd.openxmlformats-officedocument.wordprocessingml.document|text/.*|application/zip');
          allow read: if isAdminStorage();
          allow update, delete: if isAdminStorage();
        }

        function isAdminStorage() {
          return request.auth != null
            && request.auth.token.email_verified == true
            && request.auth.token.email in ['webnixit@gmail.com'];
        }
      }
    }

Se le regole Storage non sono pubblicate, la richiesta viene salvata
comunque e la dashboard mostra gli allegati come "file non caricato".

7) NOTIFICHE EMAIL (EMAILJS)
------------------------------------------------------------
Il modulo invia ogni richiesta per email all'amministratore usando
solo EmailJS, configurato in
"Modulo richiesta bozza" → "Invio e notifiche":
  - EmailJS · Service ID   (Email Services, es. service_abc123)
  - EmailJS · Template ID  (predefinito: template_oafiwle)
  - EmailJS · Chiave pubblica
Non esiste un canale di riserva: se Service ID, Template ID o chiave
pubblica mancano, l'email non parte e la richiesta resta archiviata in
Firestore (visibile nella dashboard).

Parametri disponibili nel template EmailJS:
  {{messaggio}}  testo completo e ordinato della richiesta
  {{consensi}}   una riga per ogni casella del modulo, con il testo
                 della casella e «Acconsentito» / «Non acconsentito»
  {{nome}} {{email}} {{attivita}} {{budget}} {{riferimento}}
  {{pagina}} {{subject}} {{to_email}} {{reply_to}}

Il modello HTML pronto, con la grafica del sito, è in
templateemailjs.txt: si incolla nel template EmailJS e va usato con
il dominio del sito tra gli Allowed origins dell'account.
Gli Allowed origins sono obbligatori: senza di essi l'API EmailJS
rifiuta la chiamata.

Ogni email contiene nome, email (rispondi direttamente al cliente),
attività, budget, riferimento, pagina di provenienza, consensi e le
risposte raggruppate per step.

L'invio email è indipendente dal salvataggio in Firestore: se il
database non risponde l'email parte comunque (e viceversa la richiesta
resta archiviata anche se EmailJS non risponde).

In alternativa si può usare il campo "Webhook notifica" con un URL di
Zapier, Make, n8n o una Cloud Function che riceve lo stesso JSON.
